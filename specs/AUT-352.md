# AUT-352 — Verified manufacturer model and specification catalog

## Goal

Build a versioned Catalog module that resolves a normalized manufacturer, exact model, and optional serial to a verified model revision. Enrich Intake and Inventory with equipment type, manufacture year/range, dimensions, weight, capacity, utilities, and configuration while preserving official-source provenance and human control over Machine type and actual measurements.

## Ticket Summary

- Cover Dexter, Speed Queen, Electrolux, Maytag, Huebsch, and Continental, the six manufacturers in the supplied Inventory workbook.
- Create a `2026-09-23` snapshot of every commercial washer/dryer variant discoverable in the listed official public indexes; do not claim undocumented historical completeness.
- Treat the 53 distinct workbook model strings as a minimum coverage benchmark, not a catalog limit. Catalog every in-scope model found in the official public sources, then report each workbook string as exact, alias, ambiguous, or unsupported without fabricating a match.
- Store manufacturers/aliases, model families/variants, immutable spec revisions, sources, field evidence, and versioned serial-date rules in Catalog-owned tables.
- Resolve only approved revisions through `resolveModel({ manufacturer, model, serial? })`; punctuation differences require an approved alias.
- Distinguish serial-derived manufacture year/range from model production range; return `unknown` when an official rule cannot resolve it.
- Suggest Washer, Dryer, or Other in Intake only after an exact approved model
  resolution. A stacked washer/dryer maps to Other; stack dryers remain Dryer.
- The suggestion is display-only and never populates or overwrites the worker-attributed Machine type required by ADR 0015.
- Link a committed or identity-updated Machine to the exact approved spec
  revision used. Existing links remain pinned when later revisions arrive.
- Let Inventory store actual measured/verified dimensional and weight overrides. Effective specs prefer actual values, then the pinned catalog revision; existing `capacityLb` is the Machine-specific capacity override when present.
- Seed data is a code-reviewed, idempotent snapshot; runtime paths perform no internet lookup.

## Expected Output

- `npm run catalog:import` validates and idempotently imports one approved snapshot for all six manufacturers.
- `npm run catalog:coverage` produces
  `docs/catalog/AUT-352-coverage.md` with source/model counts and all workbook
  model strings grouped by exact, alias, ambiguous, or unsupported resolution.
- Intake shows a labeled exact-match type suggestion, but the worker still chooses and saves Machine type.
- Machine detail shows pinned revision, year result, catalog specs/provenance, actual overrides, and sourced effective values.
- Catalog list/detail API responses let authenticated staff inspect approved
  models and sources without exposing a mutation or silent-approval path.

## Non-Goals

- Do not scrape/crawl sites, bypass controls, or schedule retrieval; governed ingestion is AUT-392.
- Do not call Catalog, manufacturer sites, or general search from OCR providers,
  recognition policy, or recognition persistence.
- Do not fuzzy-match, infer from appearance, or accept an LLM guess as a catalog fact.
- Do not silently approve changed external data or mutate approved revisions.
- Do not calculate freight, pallet dimensions, marketplace price, or valuation.
- Do not redesign Intake, Machine identity, or unrelated application navigation.

## Reuse Audit

Reused (from the Reuse Map and live code):

- Existing Nest module/controller/service/repository pattern and explicit ports.
- Existing database connection, transaction, audit/outbox mutation recorder,
  internal dispatcher, role guard, Zod response parsing, and PGlite fixtures.
- Existing Machine identity events, Intake read path, worker type command,
  Machine detail screen, and optimistic version conventions.
- Existing workbook reader dependency for the read-only coverage command.

New code justified because:

- Catalog is an accepted separate domain with no current schema or interface.
- Versioned official-source evidence and serial rules are different from OCR
  evidence and Inventory's physical Machine state.
- Actual dimensional/weight overrides need Inventory ownership and explicit
  catalog-versus-actual precedence; no current fields support them.

Do not duplicate:

- Authorization checks, event delivery, idempotency, Machine lookup, Intake
  readiness, OCR normalization, type selection, or web request parsing.
- Manufacturer/model aliases in resolver code; aliases belong in catalog data.
- Catalog facts onto `inventory_machine`; keep the pinned revision/link separate.

Escalated to human:

- None. Unknown serial encodings and unmatched workbook models are explicit
  supported outcomes, not reasons to guess or block implementation.

## Implementation Plan

1. Add Catalog/override contracts and exact normalization rules: NFKC, trim,
   case normalization, and whitespace collapse; punctuation changes require an
   approved model alias and collisions resolve as ambiguous.
2. Add tables for manufacturers/aliases, families, variants/aliases, sources,
   immutable spec revisions, field evidence, typed serial rules, snapshot
   imports, Machine resolutions, and Inventory actual overrides.
3. Implement Catalog repository/service behind `CATALOG_OPERATIONS`. Read only
   approved revisions; return `exact`, `ambiguous`, `unsupported`, or
   `insufficient_input` plus `exact`, `range`, or `unknown` manufacture date.
4. Implement only reviewed serial decoder types. Validate rule configuration at
   import; never execute stored code. A failed rule yields unknown, not an error
   or guessed year.
5. Curate the six-manufacturer snapshot from official public documents. Every
   non-null spec field must cite a source ID and page/section/table locator;
   retain official units and normalized inch/pound values.
6. Make snapshot import transactional and idempotent by dataset ID/checksum.
   Reject changed content under an existing ID and never update an approved
   revision in place. Record one system audit/outbox mutation per import.
7. Build the coverage command from the read-only workbook. Normalize the
   existing `Speedqueen` spelling through an approved manufacturer alias and
   report every distinct model string without serial values.
8. Add read-only authenticated Catalog list/detail endpoints. Grant
   `catalog.read` to all existing application roles; keep snapshot mutation CLI
   only in this slice.
9. Decorate Intake details with a suggestion only for exact approved matches.
   Show it near the selector as advisory text and never call the existing type
   mutation automatically.
10. Register an Inventory-owned event handler for Machine create/identity
    update. Resolve through Catalog and upsert a versioned resolution record;
    pin exact matches, retain non-match status, and rely on outbox retry.
11. Add Inventory actual override persistence and Machine-detail composition.
    Return per-field catalog, actual, and effective values; actual wins, then
    Machine `capacityLb`, then the pinned catalog revision.
12. Extend Machine detail UI with year/spec/source display and authorized actual
    width/depth/height/weight editing; do not turn catalog values into editable
    Inventory identity fields.
13. Add manifest, resolver, serial-rule, import, integration, component, and
    browser tests, then run the complete workspace gates.

## Constraints

- Catalog owns shared model knowledge; Inventory owns physical Machine identity
  and actual overrides. Neither module reads the other's tables directly.
- Catalog resolution is deterministic, evidence-backed, and exact. No fuzzy or
  probabilistic fallback may create a link or a type suggestion.
- A catalog outage/failure never changes OCR evidence, recognition readiness,
  Candidate confirmation, worker type, or Batch Commit eligibility.
- Approved revisions are immutable. New information creates a new revision;
  existing Machine links remain reproducible and pinned.
- Preserve source URL, title, retrieved time, document revision/date, checksum,
  and field locator. Do not store copied full webpages or copyrighted manuals.
- Do not log serials, workbook rows, source document bodies, OCR/provider data,
  secrets, PII, or full catalog payloads.
- Follow `AGENTS.md`, preserve unrelated dirty-worktree changes, and keep all
  existing public contracts backward-compatible through additive optional data.
