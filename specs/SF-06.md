# SF-06 — Inventory spreadsheet staging and import

## Goal

Import William's current XLSX/CSV inventory through an Owner-reviewed staging boundary. Preserve the source file and every source row, surface ambiguity and duplicates, and create authoritative provisional Machines only after explicit approval. Retrying upload or commit must not duplicate Import Runs or Machines.

## Ticket Summary

- Add an `imports` API module and Owner UI. Imports owns source-workbook evidence, parser policy, staging rows, approval, commit provenance, and reports; Inventory remains the only module allowed to create or match Machines.
- Accept only `.xlsx` and UTF-8 `.csv` uploads from Owner Admin. Require `Idempotency-Key`, a selected existing Acquisition Load, and one bounded file. Do not accept `.xls`, `.xlsm`, macros, executables, NUL-containing CSV, or extension/content mismatches.
- Store source bytes privately through the existing storage adapter behind a shared storage-provider module. Import owns immutable source metadata: generated storage key, original filename for authorized display only, media type, byte count, SHA-256, uploader, and timestamp. Never use the filename as a path/key or log it.
- Parse without evaluating formulas, macros, links, or embedded code. Bound archive/file bytes, worksheets, rows, columns, and cell text. Preserve formula text plus cached result in raw evidence but never derive an authoritative fact from a formula unless that target field has an explicit mapping.
- Make the Import Run source identity and staged rows immutable. Run lifecycle/version may progress `staged -> approved -> committed`; a failed commit becomes `commit_failed` and is retryable. Approval selections and commit mappings are append-only evidence.
- Retain exact worksheet name, one-based source row number, original headers/cells in JSON-safe typed form, normalized candidate fields, classification, and stable finding codes. Empty spreadsheet rows do not create staging rows.
- Map the supplied workbook deliberately:
  - `Make -> manufacturer`, `Model -> model`, `Serial -> serial`.
  - Preserve serials as strings. Integral numeric serial cells become non-exponential decimal strings; text retains trimmed source text. Never coerce through JavaScript floating-point formatting that changes digits.
  - Machine type is `other` with warning `machine_type_unknown`; do not infer washer/dryer from model text.
  - `In Inventory -> inventoryState=on_hand`.
  - `Purchased (Shipped)` is `legacy_sold_shipped_unsupported` and non-committable because sales/shipment state is not inventory state.
  - `Finish`, `Price`, `Year`, `Month`, testing, cleaning, and repair columns remain source evidence only. Do not put price or production history into Machine identity.
  - Missing voltage, phase, fuel, model, manufacturer, or serial stays null. Model and serial are never guessed.
- Normalize only for matching. Retain candidate display text. Recognize an explicit manufacturer alias map for matching (`Speedqueen -> Speed Queen`) while preserving the original raw value and recording `manufacturer_alias_applied`.
- Classify rows as `ready`, `warning`, or `error`. Errors cannot be approved. Warnings require explicit row selection; no row is selected automatically.
- Inventory owns matching and commit behavior through a narrow import port:
  - analyze exact normalized manufacturer+serial matches inside the run and against existing Machines;
  - flag serial-only and manufacturer+model likely matches without merging;
  - recheck matches at commit time to prevent approval/commit races;
  - create imported Machines through the caller-supplied database transaction, using existing normalization, histories, and Operations recorder.
- Duplicate findings are visible and stable. Never auto-merge, update an existing Machine, verify identity, or silently discard a row. A warned row may be explicitly approved and creates a separate provisional Machine.
- Approval takes a version and exact source-row selection, rejects any error row, and records actor/time/selection. The source Load must still exist. Approval cannot be changed after it is recorded; create a new Import Run to choose a different set.
- Commit the complete approved selection in one database transaction. Each created Machine starts provisional, uses `sourceKind=spreadsheet_import`, uses the selected Load, and has a unique Import Row -> Machine provenance record. Any unexpected failure rolls back all Machines, histories, mappings, audit, and outbox entries; record only a safe failure code in a separate transition.
- Make commit intrinsically and operationally idempotent: lock the run, enforce one mapping per source row, and use the Operations idempotency coordinator with target type `import_run`. A completed retry returns the existing result; changed key fingerprints conflict; concurrent commits cannot fork records.
- Record privacy-safe Operations actions for staged, approved, committed, and commit-failed transitions. Each imported Machine also emits the canonical `inventory.machine.created` action within the same transaction.
- Provide an Owner-only CSV result report generated from stored evidence: row number, classification, stable findings, approval/commit result, and Machine ID. Escape spreadsheet-formula prefixes in CSV. Provide authorized source-file download; never expose object keys or public URLs.
- Add `/admin/imports` with upload/Load selection, runs, filters, counts, row preview, findings, approval selection, commit confirmation, source download, and result report. The API remains the authorization boundary.

## Codegraph Findings

- `InventoryRepository.createMachine` owns normalization, evidence, Load/Location validation, Operations recording, and idempotency but starts its own transaction. Import needs an Inventory-owned method accepting the Import transaction's executor; calling the public method per row would make partial commits possible.
- `InventoryOperations` is already the explicit module seam and is consumed by Files. Extending a narrow Inventory import port has lower blast radius than exposing repository/table access.
- `StorageAdapter` has local and S3 implementations and seven callers, but `FilesModule` currently creates and retains the provider token. Extracting provider composition is required for reuse; Import must not duplicate it or widen public attachment MIME types.
- `MutationRecorder` already has ten cross-domain callers and accepts `DatabaseExecutor`; Import can get atomic audit/outbox behavior without alternate SQL.
- `IdempotencyCoordinator.complete` currently permits only Load/Location/Machine targets. Extend it to `import_run` while retaining hashed keys and canonical fingerprints.

## Constraints

- Source bytes, checksum, source facts, raw rows, and staged candidates never change after staging.
- No authoritative Machine exists before approval and commit. Error rows never commit. Warning rows require explicit selection.
- One Import Row maps to at most one Machine; one committed Machine maps back to exactly one source row/run.
- The complete approved selection commits atomically. Import does not call a transaction-opening Inventory method inside its transaction.
- Import never writes Inventory tables directly. Inventory never parses workbook formats or owns Import lifecycle.
- Source and reports are private Owner data; storage keys, bytes, raw rows, filenames, serials, and notes never enter logs/audit summaries/outbox errors.
- Formula text is inert evidence. CSV report cells are escaped against spreadsheet formula injection.
- Upload and commit keys are hashed, scoped to actor/operation/run, and replay only stable target references.
- The supplied workbook remains unmodified and untracked.
