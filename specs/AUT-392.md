# AUT-392 — Automatically discover and publish verified model specifications

## Goal

After Google Vision OCR and OpenAI field assignment establish a supported manufacturer and exact model, automatically research that model through OpenAI Responses API web search when the approved Catalog has no exact match. Publish only fields that pass a deterministic official-source policy, then expose height, width, depth, weight, capacity, configuration, production range, and any source-backed serial-year rule in Intake and Machine detail without a human approval step or any effect on Intake readiness.

## Ticket Summary

- Keep OCR/field assignment and Catalog discovery as two separate provider calls in one receiving workflow.
- Start Catalog discovery from a ready targeted recognition result; Machine creation/identity-update remains a fallback trigger.
- Search the unrestricted public web: send no `allowed_domains` filter to OpenAI.
- Use the accepted manufacturer and exact model only. Never use search to reconstruct unreadable identity characters.
- Reuse an existing exact approved Catalog revision without another provider call.
- Deduplicate discovery by normalized manufacturer/model plus provider/model/prompt/schema/policy versions so repeated Machines reuse one result.
- Automatically publish a revision; there is no approval queue, approval screen, or manual approval action.
- The automatic publication gate accepts only exact-model, conflict-free fields cited to an HTTPS source on an already trusted official manufacturer hostname.
- Third-party, distributor, reseller, marketplace, family-only, conflicting, or unsupported fields remain unknown and cannot become effective Machine facts.
- Preserve field-level URLs, locators, original values/units, source class, retrieval time, provider/model versions, token usage, web-search call count, pricing snapshot, estimated cost, and a response fingerprint.
- Do not persist the raw provider response, complete prompt, serial, or copied webpage/manual body.
- Existing typed serial-rule schemas are the only executable year-decoding forms. Arbitrary prose or generated code cannot become a rule.
- Provider failure, no verified result, disabled configuration, or unresolved manufacturer domain never blocks recognition, type selection, Batch Commit, or Machine creation.
- Existing actual Machine measurements continue to override Catalog defaults.

## Expected Output

- A ready Intake candidate with an unsupported exact model automatically queues one bounded Catalog discovery run.
- The Intake review shows `Researching specifications`, verified dimensions/specs with source links, or `No verified specifications found`; it never adds an approval control.
- A successful strict-policy result is imported as an immutable automatically published Catalog revision and is reused by later Candidates and Machines.
- Machine detail shows the discovered revision through the existing catalog/actual/effective precedence, including automatic-publication provenance and usage/cost metadata.
- A deterministic fake provider drives unit, integration, and browser acceptance tests; live OpenAI remains an explicit deployment smoke test.

## Non-Goals

- Do not combine web search with the OCR field-assignment request.
- Do not send image bytes, OCR blocks, serial numbers, Load data, user data, or private URLs to Catalog discovery.
- Do not create a human approval or correction workflow.
- Do not accept non-official sources as verified defaults.
- Do not scrape/crawl sites, bypass access controls, download or retain manuals, or schedule source monitoring.
- Do not add fuzzy manufacturer/model matching, infer specs from related models, or calculate freight/pallet measurements.
- Do not change worker-selected Machine type, OCR acceptance, Batch Commit eligibility, or Inventory actual-spec precedence.

## Automatic Publication Policy

Every published revision must satisfy all of the following:

1. Manufacturer resolves exactly or through an approved Catalog alias to one existing manufacturer.
2. Trusted official hostnames come only from that manufacturer's already approved Catalog sources; matching is exact hostname or a subdomain of that hostname, never a substring.
3. OpenAI's search itself is unrestricted, but every accepted field cites an HTTPS URL present in the API's returned web-search source list and on a trusted official hostname.
4. The structured result states that the exact normalized model appears in the cited source and supplies a non-empty page/section/table locator.
5. Model and equipment class have accepted official evidence. At least one requested specification or production/serial rule must also pass.
6. Each scalar field has one conflict-free normalized value. Conflicting values are dropped, not averaged or selected by confidence.
7. Metric/imperial conversion is deterministic and range checked. Provider-normalized values that disagree with the supplied official value/unit are rejected.
8. Width/depth/height, weight, capacity, year ranges, electrical values, fuel, and configuration satisfy bounded shared schemas.
9. Serial rules must parse as an existing `CatalogSerialRuleSchema` type and cite official exact-model or documented family evidence. Unknown rules return unknown year.
10. Publication is recorded as `automatic_official_source_policy`; source/revision history is immutable and audited.

## Codegraph Findings (live, this ticket)

- `CatalogOperations` currently has three callers: Inventory Machine enrichment, Intake read decoration, and Inventory Machine detail composition.
- `inventory.intake.recognition.completed` is persisted only after Candidate facts and run state commit; its target is the recognition-run ID.
- `CatalogEnrichmentService` already handles `inventory.machine.created` and `inventory.machine.identity_updated` through the durable event registry.
- `CatalogRepository.resolve()` reads approved revisions only and `resolveAndLinkMachine()` protects identity-version/fingerprint ordering.
- Catalog source rows already preserve URL/title/retrieval/checksum, while field evidence preserves locator and official value/unit.
- Existing snapshot import supplies immutable/idempotent publication mechanics but has no discovery run, source class, automatic-publication mode, or usage/cost provenance.
- Intake's provider HTTP helper contains recognition-specific image types/errors and cannot be imported across the Inventory domain boundary unchanged.
- Candidate detail already supports an additive Catalog suggestion and Machine detail already renders catalog/actual/effective values.

## Reuse Audit

Reused:

- Exact Catalog normalization/alias resolution, seed-manifest validation, immutable revision/source/evidence persistence, serial-rule evaluator, effective-spec precedence, Operations outbox, protected API/client parsing, route-state handling, and current UI surfaces.
- Existing OpenAI Responses request style, strict JSON schema, safe request ID, bounded timeout/output, and deterministic fake-provider testing pattern.

New code justified because:

- No governed runtime discovery port, run record, official-host policy, provider usage record, or automatic-publication provenance exists.
- A neutral provider HTTP seam is required before a second domain can reuse transport safety without depending on Inventory recognition internals.

Do not duplicate:

- Manufacturer/model normalization or aliases, Catalog import validation, serial evaluation, Operations retry logic, source rendering, effective-spec precedence, or web transport/error handling.

Escalated to human:

- None. The user explicitly removed human approval and chose automatic publication under deterministic verification.

## Implementation Plan

1. Prefactor generic bounded provider HTTP transport to a neutral platform helper and prove existing recognition adapter behavior remains unchanged.
2. Add additive contracts/configuration, the forward-only discovery migration, source class, publication mode, and discovery-run usage/cost provenance.
3. Implement the provider-neutral Catalog discovery port, deterministic fake, and OpenAI Responses adapter using `web_search`, `tool_choice: required`, high search context, included source URLs, strict output, low reasoning, and no domain filter.
4. Implement deterministic automatic verification: trusted host derivation, URL/source membership, exact-model evidence, conflict removal, unit conversion/ranges, typed serial-rule validation, and no-result outcomes.
5. Claim discovery idempotently by normalized identity and version tuple, call the provider outside database transactions, then atomically persist the completed run and publish one immutable revision through existing manifest/repository invariants.
6. Register recognition-completed prefetch and Machine-event fallback. Temporary provider failures retry through Operations; terminal no-result outcomes are reusable and do not retry on every Machine.
7. Extend Intake reads and review UI with pending/verified/no-result state. Extend Catalog/Machine provenance rendering with automatic mode, sources, tokens, calls, pricing version, and estimated cost.
8. Add focused unit/integration/browser coverage, then run every workspace gate and one explicit live-provider smoke test when credentials are present.

## Constraints

- Search may discover any domain, but automatic publication accepts only existing trusted official manufacturer hosts.
- No provider call occurs in an HTTP GET, controller, React component, repository transaction, OCR adapter, or deterministic policy.
- No network call holds a database transaction or outbox lease beyond configured limits.
- One normalized model/version tuple produces at most one active discovery run; at-least-once delivery cannot duplicate revisions.
- Store raw usage and the price rates/version used for estimates; billing dashboards remain authoritative.
- Do not log credentials, prompts, raw output, serials, complete provider payloads, sensitive URLs, or source bodies.
- Preserve all user data and unrelated dirty-worktree changes.
- Follow `AGENTS.md`, exact module ports, runtime validation, authorization, audit/outbox, and deterministic fake-test conventions.

## Done Criteria

- One supported nameplate identity can produce verified sourced specs without a human approval step.
- Unrestricted search cannot publish a third-party or lookalike-domain value.
- The same model across multiple Candidates/Machines consumes one discovery run for the same version tuple.
- Intake remains usable and committable during pending, failed, disabled, or no-result discovery.
- Published facts are immutable, field-cited, source-classified, audited, cost-attributed, and visible in Intake/Catalog/Machine detail.
- Manufacture year is exact/range only through a valid official typed serial rule; otherwise it is explicitly unknown.
- Actual Machine measurements still win over automatically discovered defaults.
- Deterministic end-to-end tests and all workspace gates pass with no new approval UI, duplicate business rule, or unrelated refactor.
