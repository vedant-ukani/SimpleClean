Where should Simple Clean run OCR?

The Mac mini is capable of testing PP-OCR. Production placement depends more on monthly image volume and reliability than raw model capability.

This Mac mini

  • Apple M4, 10 CPU cores, 16 GB RAM, ARM64: sufficient for standard PP-OCR CPU inference.
  • Python 3.9 meets PaddleOCR's current Python requirement.
  • Only about 5.3 GB is free: free 15–25 GB before installing environments, models, caches, and logs.
  • Use it for evaluation or a low-volume internal pilot—not as the first production server.

PaddleOCR reports an Apple M4 benchmark for its PP-OCRv6 tiny tier, but real latency must be measured on our resized warehouse images. See the PaddleOCR project page.

Accuracy is undecided

There is no trustworthy public benchmark comparing Google Vision and PP-OCR on our machine-nameplate photos. Published PaddleOCR benchmarks and Google product claims use different datasets. Test both on the same labeled set and compare exact serial/model match, false automatic approvals, recapture rate, and latency.

Current recommendation

  1. Free disk space and run PP-OCR locally on this Mac.
  2. Send the same permissioned 200–500 photos to Google Vision.
  3. Use the winner on exact-field accuracy, subject to a zero-false-auto-accept target.
  4. If results are close and volume is below roughly 17,000 images/month, launch with Google Vision.
  5. If PaddleOCR wins materially, privacy matters, or volume is high, deploy it on a monitored Linux VM.
