Verify supervised Intake approval

Walk one real-looking machine through Gemini grouping, Google Vision verification, human correction, and the single approval action that adds it to Inventory.

Readiness snapshot

  • Gemini gemini-3.6-flash text connectivity passed.
  • The Google Vision benchmark previously passed on the shared corpus.
  • The local web app is healthy on :3000; the API is healthy on :3001.

Safety rule: unset confidence floors keep approval human-supervised. Provider output alone never creates an Inventory Machine.

1. Follow the exact path

Loads
Choose View Load.
Start
Choose Start Laundrorama intake.
Review
Open Photo intake review.

For the first test, use one machine and two or three private photos: one full-machine view plus one sharp, readable nameplate view (and a second plate angle if useful).

2. Check recognition, then take ownership

  1. Choose Choose arrival/nameplate photos and wait for Ready for review.
  2. Confirm the photos form one recognized Machine group and inspect the visible facts: type, manufacturer, model, serial, voltage, phase, and fuel.
  3. If a fact is wrong, edit it in the candidate editor, choose Save facts, then choose Confirm candidate. The saved correction—not the provider suggestion—is what approval uses.
  4. If the evidence is unclear, follow Upload the requested evidence, wait for the recapture result, and resolve the new review state. If recognition cannot resolve the evidence, use Continue with manual review.

What a healthy exception looks like

Blur, glare, cutoff, unreadable text, conflicting readings, or an ambiguous group should become a targeted recapture or manual review—not a guessed fact. Do not approve until every candidate is confirmed.

3. Approve one atomic batch

  1. Choose an active Destination location.
  2. Read the total candidate count and confirm every candidate is ready.
  3. Choose Approve and Add to Inventory, then accept the irreversible confirmation dialog.

Cancel the confirmation once as a negative test: no approval request should be sent, the batch should remain open, and no Machine should appear.

4. Verify the result

  • The status reads committed and the approval control is disabled.
  • A created Machine link appears, along with View Inventory.
  • The corrected manufacturer/model/serial values appear on the created Machine.
  • The Machine is on_hand, still provisional, and assigned to the selected destination.
  • Reload the Intake page: the committed status and Machine links persist.
  • Repeat approval or replay the request: it does not create a duplicate Machine.

Pass or fail?

Pass means the full path completes with the corrected values, one provisional Machine, the right destination, persistent committed state, and no duplicate after replay.

Fail means approval happens before confirmation, a recapture/incomplete/canceled path creates anything, corrected values disappear, the destination is wrong, or a repeated approval creates another Machine.

Report the exact navigation path, the labels reached, recognition/recapture outcome, candidate correction, destination, created Machine link, committed/reload result, and duplicate check. Never report API keys, raw provider responses, private image contents, or filenames.
