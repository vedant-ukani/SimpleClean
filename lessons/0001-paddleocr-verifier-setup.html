PaddleOCR as the INT-02 verifier

Gemini interprets the machines and groups their photos. PaddleOCR independently reads visible text. Automatic approval happens only when both agree strongly enough.

Decision

Start with the General OCR pipeline (PP-OCR), not PaddleOCR-VL. It is the independent text-reading check we need; a second vision-language model would duplicate Gemini's role and its failure modes.

Runtime shape

Simple Clean API
Sends bounded, metadata-stripped images.
Compatibility bridge
Translates our batch JSON into PaddleX's per-image API.
PaddleX OCR server
Returns text, confidence, and polygons.

Important integration detail

The stock PaddleX endpoint is POST /ocr with {"file": "base64", "fileType": 1}. Our adapter sends {"model": "...", "images": [...]} and expects normalized lines. Therefore, pointing the app directly at http://localhost:8080/ocr will not work. Add a small bridge at /recognize, or change the TypeScript adapter.

1. Run PaddleOCR locally

python3 -m venv .venv-paddleocr
source .venv-paddleocr/bin/activate
python -m pip install --upgrade pip

# Install the correct CPU/GPU PaddlePaddle build using the official selector first.
pip install paddleocr
paddlex --install serving
paddlex --serve --pipeline OCR --host 127.0.0.1 --port 8080 --device cpu

The first run downloads model files. Begin on CPU for validation; measure before buying or configuring GPU capacity. See the General OCR guide and serving guide.

2. Bridge contract

The bridge accepts the request already emitted by Simple Clean:

{
  "model": "pp-ocr",
  "images": [{
    "photoId": "uuid",
    "mediaType": "image/jpeg",
    "imageBase64": "base64..."
  }]
}

For every image it calls PaddleX POST /ocr, converts each polygon to one pixel bounding rectangle, and returns the adapter-friendly results form. The existing adapter normalizes those pixel coordinates using the source image dimensions:

{
  "results": [{
    "photoId": "uuid",
    "lines": [{
      "text": "MODEL SC30",
      "confidence": 0.98,
      "bbox": [160, 240, 1280, 360]
    }]
  }]
}

3. Configure Simple Clean

INTAKE_RECOGNITION_ENABLED=true
INTAKE_RECOGNITION_SEMANTIC_PROVIDER=gemini
INTAKE_RECOGNITION_SEMANTIC_MODEL=<approved-gemini-model>
INTAKE_RECOGNITION_SEMANTIC_API_KEY=<secret>

INTAKE_RECOGNITION_VERIFIER_PROVIDER=paddleocr
INTAKE_RECOGNITION_VERIFIER_MODEL=pp-ocr
INTAKE_RECOGNITION_VERIFIER_ENDPOINT=http://127.0.0.1:8090/recognize

# Starting values only; tune from labeled evaluation data.
INTAKE_RECOGNITION_GROUP_FLOOR=0.90
INTAKE_RECOGNITION_FIELD_FLOOR=0.90
INTAKE_RECOGNITION_OCR_FLOOR=0.90

Use HTTPS for staging/production. Keep the API key blank only if the OCR bridge is private and network-restricted; otherwise configure bearer-token authentication.

4. Prove accuracy before enabling auto-approval

npm run evaluate:intake-recognition -- \
  --allow-live \
  --manifest /absolute/path/to/intake-recognition.manifest.json

Use real, permissioned warehouse photos: sharp, blurry, glare, oblique angles, multiple machines, duplicate views, and unreadable labels. Optimize first for zero false auto-accepts; then reduce unnecessary recaptures.

What to verify

  • PaddleOCR returns the exact serial/model text visible in the photo.
  • The bridge preserves the correct photoId for every line.
  • Boxes are normalized to 0–1 and stay inside image bounds.
  • Low-confidence or conflicting readings trigger recapture, not guessing.
  • Provider timeouts and malformed output fail closed.
